Structure

職務経歴書の基本構成

採用担当者が読みやすい構成は決まっています。この順番で書きましょう。

1
職務要約（3〜5行）

自分の強みとキャリアの方向性を凝縮して伝えるセクション。採用担当者が最初に読む最重要部分です。

💡 ポイント：「何年・何を・どのレベルで」の3要素を含め、あなたを雇うメリットを一言で言えるように書く。
2
スキルセット（技術スタック）

使用できる言語・フレームワーク・インフラ・ツールをカテゴリ別に整理します。習熟度も明記すると◎。

💡 ポイント：「業務使用3年以上」「個人開発レベル」など習熟度を正直に書くと信頼感が上がる。
3
職務経歴（プロジェクト単位で記載）

会社単位ではなくプロジェクト単位で記述します。各プロジェクトで「役割・規模・技術・成果」を書きます。

💡 ポイント：成果は必ず数値化。「改善した」→「レスポンスタイムを40%削減」のように具体的に。
4
自己PR（強み・志向性）

技術的な強みだけでなく、仕事への向き合い方・チームでの動き方なども書きます。

5
資格・学習（オプション）

AWS認定・情報処理技術者・英語力（TOEIC）など。GitHubリンク・技術ブログも有効。

Examples

NG例・OK例で学ぶ書き方

📝 職務要約の書き方

NG
Webエンジニアとして5年間働いています。バックエンドもフロントエンドも経験しており、チームで協力して開発してきました。新しい環境でも頑張ります。
OK
Go/TypeScriptを中心としたWebバックエンド開発経験5年。スタートアップ2社にて自社SaaSのAPI設計・マイクロサービス化をリード。チーム5名のテックリードとして月間100万リクエスト規模のサービスを安定運用。次のフェーズでは分散システムの設計・運用に携わるポジションを希望しています。

📊 実績の書き方

NG
・パフォーマンス改善を実施しました
・DBクエリの最適化を行いました
・チームでCI/CDを導入しました
OK
・N+1問題の解消・インデックス最適化によりAPIレスポンスタイムを平均1.8秒 → 0.3秒に改善（83%削減）
・スロークエリ上位10件の改善によりDBサーバーCPU使用率を85% → 40%に削減
・GitHub Actions + ArgoCDでCI/CDパイプライン構築。デプロイ時間を1時間 → 8分に短縮

🛠️ スキルセットの書き方

NG
言語：Java, Python, JavaScript, TypeScript, Go, Ruby, PHP, Swift, Kotlin, C++, Scala（すべて経験あり）
OK
業務使用（3年以上）：Go, TypeScript, Python
業務使用（1〜2年）：Java, Ruby on Rails
個人・学習レベル：Rust, Kotlin
フレームワーク：Echo(Go), Next.js, FastAPI
インフラ：AWS(ECS, RDS, S3, CloudFront), Terraform, Docker, k8s
Checklist

提出前チェックリスト

✅ 内容チェック

✅
職務要約は3〜5行で自分の強みが伝わるか
✅
実績に数値・規模感が含まれているか
「改善した」→「〇〇%削減」「〇〇万件処理」など
✅
プロジェクトごとに自分の役割が明確に書いてあるか
「チームで開発」ではなく「5名チームのバックエンドリード」
✅
スキルセットに習熟度が書いてあるか
✅
志望企業の求める技術・経験と合致した内容になっているか

✅ 形式チェック

✅
ボリュームは2ページ以内か（3ページ超はNG）
✅
フォントサイズは10〜11pt、余白は適切か
✅
誤字脱字・会社名の正式表記をチェックしたか
✅
PDF形式で保存済みか（Word形式は崩れる場合あり）
✅
ファイル名は「氏名_職務経歴書_日付.pdf」になっているか
Tips

通過率を上げる3つの裏技

🔍

JD（求人票）と言葉を合わせる

求人票に「マイクロサービス」と書いてあれば、自分の経歴にも同じ言葉を使う。ATS（採用管理システム）でキーワードマッチングされることが多い。

📊

実績は「Before→After」で書く

「〇〇を改善した」より「1.8秒→0.3秒に短縮（83%削減）」の形式。比較があると成果の大きさが伝わりやすい。

🔗

GitHubリンクを必ず載せる

技術系企業の採用担当は高確率でGitHubを確認する。OSSへのコントリビュートや個人開発のコードは強力な差別化になる。
